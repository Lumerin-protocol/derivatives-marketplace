# Fees

Hash Power Perps charges a **match fee** on every fill. There are no deposit,
withdrawal, or cancellation fees. This page explains how trade fees are
computed and where they go.

---

## Match fees (taker & maker)

When two orders match, both sides are charged a fee proportional to the
matched **notional**:

```
notional = tradePrice × matchedQuantity / 10^QUANTITY_DECIMALS

takerFee = notional × takerFeeBps / 10_000
makerFee = notional × makerFeeBps / 10_000
```

- The **taker** is the incoming (aggressive) order that crossed the book; the
  **maker** is the resting order that was filled.
- `takerFeeBps` and `makerFeeBps` are owner-configured basis points and are
  **signed**. A negative maker fee is a **rebate** (the maker is paid), which
  is why fees are represented as signed values internally.

## Minimum taker fee

The taker fee has a floor equal to `liquidationFee`:

```
takerFee = max(notional × takerFeeBps / 10_000, liquidationFee)
```

This guarantees every trade contributes at least enough to cover the
potential liquidation cost of one party. Note this is the **only** role
`liquidationFee` still plays actively — its keeper-payout role during
liquidation is currently disabled (see
[Margin & Liquidation](./05.Margin-and-Liquidation.md)).

## Where fees go

Fees settle through the vault's **insurance fund** account:

```
fee > 0  → participant pays the insurance fund
fee < 0  → insurance fund pays the participant (rebate)
```

The insurance fund is the same reserve that backs PnL settlement, funding,
and bad-debt absorption — so trading fees directly strengthen the buffer
that protects winners against defaulting counterparties.

## What is *not* charged a fee

| Action                 | Fee                                            |
| ---------------------- | ---------------------------------------------- |
| Depositing collateral  | None                                           |
| Withdrawing collateral | None                                           |
| Placing a resting order| None until it matches (then maker fee applies) |
| Cancelling an order    | None                                           |
| Funding                | Not a fee — a periodic transfer between traders via the fund (see [Positions & Funding](./04.Positions-and-Funding.md)) |

## Parameters

| Parameter        | Setter                                  | Meaning                              |
| ---------------- | --------------------------------------- | ------------------------------------ |
| `takerFeeBps`    | `setMatchFee(takerFeeBps, makerFeeBps)` | Taker fee in basis points            |
| `makerFeeBps`    | `setMatchFee(takerFeeBps, makerFeeBps)` | Maker fee in bps (negative = rebate) |
| `liquidationFee` | `setLiquidationFee(fee)`                | Minimum taker fee (flat, token units)|

Fee changes emit `MatchFeeUpdated` / `LiquidationFeeUpdated`, and each fill
reports the exact `makerFee` / `takerFee` charged in the `OrderMatched`
event.
